# 设计文档

> 本文档记录项目的目标、技术决策及其理由。开工前以此为准；决策变更时同步更新本文档。

## 1. 项目目标

- **用途**：作品集项目，用于扩大求职面试的广度。
- **主线背景**：Python（后端 / 数据 / AI 方向）。
- **扩展目标**：让游戏开发岗（客户端 / Gameplay）愿意给面试机会。
- **一个项目讲两个故事**：
  - 投游戏岗 → 讲游戏本体（玩法系统、性能优化、多平台输入）。
  - 投后端 / 数据岗 → 讲 FastAPI 服务、数据库、用游玩数据驱动平衡性调整。
- **展示形式**：网页链接点开即玩（电脑 + 手机）+ GitHub README（GIF、架构图、技术难点）。

## 2. 技术选型

| 部分 | 选择 | 理由 |
|---|---|---|
| 游戏引擎 | Unity 6 LTS + C# | 游戏岗招聘中出现最多的技能关键词；割草类教程资料最多 |
| C# IDE | Visual Studio 2022 Community（已安装，D 盘） | Unity 官方支持，断点调试开箱即用 |
| 输入 | Unity 新 Input System | 键盘 / 手柄 / 触屏一套抽象 |
| 后端 | Python + FastAPI | 主线技能，与游戏形成双线叙事 |
| Python 工具链 | uv | 快、现代，替代 pip/venv |
| 数据库 | Neon（免费 PostgreSQL） | Render 免费 Postgres 30 天过期，免费实例磁盘不持久化 |
| 后端托管 | Render（免费 Web Service） | 免费额度够用；注意冷启动约 30 秒 |
| 游戏托管 | itch.io | 对 Unity WebGL 压缩格式支持最好，自带社区曝光 |
| CI/CD | GitHub Actions（GameCI 构建 Unity，butler 发布 itch.io） | 自动构建 + 部署是工程能力信号 |
| 美术 | 免费像素素材包（Kenney / 0x72 DungeonTileset II 等） | 精力放在程序；README 注明出处 |

## 3. 游戏设计

- **类型**：割草 / 弹幕生存（类《吸血鬼幸存者》）。
- **主题**：暗黑奇幻像素风，骑士 / 法师对抗骷髅、蝙蝠、史莱姆。
- **平台**：网页（WebGL），电脑和手机都支持。
  - 横屏、竖屏都能玩：用自适应摄像机（随屏幕比例调整可视范围）加 UI 锚点适配，不强制旋转。
  - 电脑：WASD / 方向键 / 手柄。
  - 手机：浮动虚拟摇杆（按在屏幕任意位置即出现）；升级和菜单用点按。

### 3.1 MVP 范围

- 角色八方向移动，武器自动攻击。
- 3 种武器：环绕飞刀、直线弹幕、范围光环。
- 3 种敌人：普通追踪型、快速脆皮型、慢速肉盾型，外加 1 个 Boss。
- 经验宝石，升级时三选一（新武器或强化）。
- 刷怪强度随时间上升，坚持 10 分钟即胜利。
- 主菜单、暂停、死亡结算、重新开始。

**MVP 之后的点子（暂不做）**：角色选择、局外成长、存档。

### 3.2 性能目标

- 中端手机浏览器稳定 60 帧，同屏敌人上限约 300。
- 敌人、子弹、经验宝石全部使用对象池。
- 压缩后包体约 20MB 以内（Brotli 压缩 + 代码裁剪）。
- 每周在真机上实测一次；优化前后的帧数对比写进 README。

## 4. 后端：排行榜和游玩数据

- **排行榜**：结算时输入昵称提交，无需注册。
  - 服务端校验：分数与存活时间是否合理、限制提交频率、敏感词过滤。
- **游玩数据**：完全匿名，每局生成随机会话 ID，不收集个人信息；设备只区分手机 / 电脑。
  - 事件：`run_start`、`level_up`（选了什么）、`death`（时间、波次、击杀者）、`run_end`（胜负、得分）。
  - 页面写明：「会收集匿名游玩数据，用于平衡性分析」。
- **客户端**：针对冷启动做「加载中」状态，以及超时和重试。
- **加分项**：简单的数据看板（平均存活时间、最常见死因、升级选择率）。

## 6. 分工

- **AI 编写代码，本人负责审查**：每次交付附带审查要点和「面试可能被问的问题」。
- **提交前提**：本人能讲清改动中每个关键设计决策的理由；讲不清的地方先弄懂再提交。
- **风险**：面试时会被追问代码细节，审查要做到「能复述、能改写」，而不只是「看过」。
